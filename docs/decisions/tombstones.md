# Tombstones

Tombstones record evaluated tools and approaches that should remain absent from
the active workbench. They prevent accidental reintroduction and repeated
evaluation. Reconsider one only when its stated trigger becomes true.

This file covers decisions with no Workbench code off-switch and cross-repository architecture choices whose lesson belongs with agent-tool research. Workbench retirements that code enforces live with their enforcement: `RETIRED_SUBAGENTS` / `RETIRED_SKILLS` / `RETIRED_PI_EXTENSIONS` in `src/workbench/core.py` and the `_*_disabled` entries in `agents/shared/mcp-servers.json`, each carrying its own reason. Host package retirements remain enforced in the adjacent host repository's package manifest.

## Retired Pi harness experiments

This table is the readable memory of Pi additions that were implemented or actively exercised, not ideas that were merely discussed. The inventory was reconstructed in 2026-09 from Workbench and Dotfiles history plus past Pi, Claude, and Codex transcripts. Code-enforced extension reasons remain canonical in `RETIRED_PI_EXTENSIONS`; the table keeps the experiments discoverable as one set.

| Experiment | What was tried | Why it ended | Revisit only when |
|---|---|---|---|
| `pi-superpowers-plus` workflow package | Installed the package, its process skills, persistent workflow state, and workflow/TDD heads-up display. | Fresh sessions displayed stale workflow state, package skills collided with owned skills, and a third-party state machine became an overlapping workflow authority. The useful planning, debugging, testing, and execution practices were in-sourced selectively. | A recurring workflow demonstrably needs package-owned persistent phase state and beats repo-owned skills without stale-session signals or trigger collisions. |
| `mitsupi` package bundle | Installed the broad community bundle and evaluated its notifications, browser, GitHub, handoff, context, editing, and orchestration ideas. | Most of the bundle duplicated native Pi, trusted command-line tools, or owned skills while permanently expanding executable and metadata surface. Useful ideas such as `/consult` and context breakdown were rebuilt narrowly. | One specific Mitsupi capability solves repeated measured friction that native Pi and a small owned implementation cannot solve. Evaluate that capability alone, not the bundle. |
| Visible multipart request ledger | Required agents to print and close a numbered ledger for long prompts. | It added ceremony and awkward tone without catching a demonstrated omission. Internal request reconciliation and explicit final remaining-work status preserve the useful invariant. | Independent requests are repeatedly dropped despite the internal closeout contract. |
| Codex response-header quota and Fast-mode probe | Added speculative header parsing plus `/codex-headers` to discover five-hour, weekly, and Fast-mode state from Pi's `openai-codex` provider. | A real Codex-backed turn exposed no usable headers, so the command and speculative parser were removed rather than presenting invented state. | Pi exposes authoritative subscription-route state through a supported provider API that can be tested directly. |
| Discovery telemetry extension | Logged tool and session metadata to look for navigation, retrieval, and verification bottlenecks. | The bounded trial found no symbol-navigation problem and produced distorted metrics; ordinary transcripts did reveal weak post-mutation verification, which became a deterministic closeout concern instead. | A new bounded harness question cannot be answered from tests, transcripts, or existing runtime evidence. |
| Transcript Reader (`/reader`) | Built a custom full-screen transcript navigator with prompt and answer landmarks. | Native Pi fullscreen supplied the valuable scrolling, search, selection, links, and prompt jumps. Final-answer landmarks and compact summaries did not justify 376 lines of extension code plus tests. | Native fullscreen fails a recurring reading workflow and an upstream fix cannot address it. |
| `pi-mcp-adapter` proxy | Installed a generic MCP package and routed source integrations through it. | Owned read-only connectors replaced Google and Strava routes, Granola remained project-scoped, and the idle proxy carried roughly 200 transitive packages with no remaining job. | A remote MCP server earns recurring use that a small owned client or project-scoped adapter cannot serve. |
| Project switching (`/cd` and `/z`) | Forked the active conversation into a new session root, with explicit-path and zoxide resolution. | Agents already work across repositories with explicit paths. Re-rooting preserved stale conversation while adding session-fork lifecycle complexity; starting in the correct repository is clearer. | Repeated work proves that absolute-path operation and a fresh correctly rooted session are materially inadequate. |
| Pi-specific remote and phone surfaces | Tried the `dfs remote pi` launcher, a Pi phone PWA, Zellij web, and related session-manager layers. | The experiment mixed transport, process survival, and presentation while still giving a poor phone terminal experience. Paseo plus Tailscale became the cross-harness owner. Detailed variants and triggers live under [Terminal continuity, mobile access, and process runners](#terminal-continuity-mobile-access-and-process-runners). | Use the trigger on the specific terminal-continuity tombstone below; do not restart with another Pi-only viewer. |

| Standalone wrapper CLI (GSD-style) | Rejected | Owning the execution environment for programmatic context management means maintaining a second harness that trails vendor releases; native skills plus fresh subagent contexts cover context rot | Vendor harnesses stop exposing enough context control for a recurring workflow |
| Permanent specialist-agent roster | Retired 2026-08-26 | Even a small installed roster duplicated portable review, security, testing, and debugging skills while requiring vendor-specific rendering, sync, drift, and lint machinery; bounded task-specific delegation preserves isolated context without permanent definitions | A recurring task class repeatedly needs stable specialist instructions that a skill plus explicit delegation cannot express |
| Lights-off software factory and agent-owned merge boundary | Rejected 2026-08-27 | High-throughput first-party case studies do not establish long-term maintainability or transfer to established personal repositories. Agents may implement and review, but a human owns intent, understands the invariant, and authorizes consequential external effects and merge decisions. | Repeated measured work shows human review is the binding constraint after strong deterministic and independent agent verification, with a reversible trial and clear rollback boundary |
| [Sandcastle coding-agent orchestrator](https://github.com/mattpocock/sandcastle) | Rejected 2026-09-03 | Its useful mechanics - bounded delegation, worktree isolation, parent review, and adoption of verified changes - already exist in the managed Pi worker. Sandcastle would add a TypeScript orchestration layer, container lifecycle, branch strategies, and another configuration surface without solving a demonstrated workflow gap. Its default Docker `head` strategy also bind-mounts and writes directly to the host checkout, so the headline sandboxing does not improve the current trust boundary by default. | A recurring unattended workflow needs provider-independent container or microVM execution that the managed worker cannot supply, and measured demand justifies owning an orchestration layer. |
| Always-on multi-agent verifier fabric | Rejected 2026-08-27 | Deterministic project gates plus scoped fresh-context review provide the useful floor without a standing fleet's noise, cost, orchestration, and provenance burden. Model findings remain advisory unless converted into executable invariants. | A measured review backlog or escaped-defect class persists despite existing gates and bounded review, and a narrow verifier trial has precision and cost criteria |
| Flue durable-agent runtime in Workbench | Rejected 2026-08-27 | Flue is a framework for deployed, durable, stateful agents. Workbench configures coding harnesses and should not acquire another runtime, database, deployment model, or persistent-session abstraction without a production agent that needs them. | A concrete recurring agent must survive process restarts, expose addressable durable sessions, and cannot use an existing narrow workflow runtime |
| Managed Claude output styles | Rejected 2026-08-27 | Shared communication rules and task-specific prompts are portable and visible. Deploying vendor-specific style profiles adds another configuration surface and can mask unclear writing doctrine rather than fix it. | Distinct recurring communication modes cannot be expressed through shared rules or on-demand prompts and a profile demonstrably reduces editing effort |
| Formal ontology as a universal coding-agent guardrail | Rejected 2026-08-27 | Types, schemas, constrained tool interfaces, domain models, and deterministic validation cover ordinary software invariants with less machinery. RDF, OWL, or a reasoner is justified only when formal multi-hop inference is itself a domain requirement. | A project has a concrete inference or semantic-integration requirement that typed contracts and database constraints cannot express |
| Cloud-only or "orb-only" development | Rejected 2026-08-27 | Remote sandboxes are valuable for asynchronous or untrusted work, but local execution remains better for low-latency steering, private context, interactive debugging, and direct comprehension. Use each execution environment for the job rather than declaring one obsolete. | The local path repeatedly blocks a measured workflow and a remote environment meets privacy, observability, cost, and recovery requirements |
| Numeric code-shape rules as always-on prose | Rejected | Max-line and helper-count limits in global instructions are advice an agent may or may not weigh; they belong in deterministic project gates (linters, ratchets) | A shape regression recurs that no project-native gate can encode |
| Cursor Automations runtime | Rejected 2026-08-26; patterns retained | Scheduled and repository-event triggers, scoped tools, confidence-gated mutation, safe no-op outcomes, reruns after pull request changes, adversarial trigger handling, template distribution, and bounded deduplication state are useful. Adopting Cursor or embedding its scheduler in Pi would add a hosted control plane and product coupling when CI and the private automation layer already own execution. | A recurring workflow specifically requires Cursor's hosted runtime and cannot be expressed safely through existing automation owners |

## Terminal continuity, mobile access, and process runners

These approaches were tried or evaluated as answers to process continuity, session discovery, or phone access. They are not interchangeable: transport, process survival, and touch-friendly agent presentation are separate jobs. The adopted boundary is Tailscale for private transport, Paseo for coding-agent continuity and presentation, launchd for the Paseo daemon, project services for project processes, and CI or operating-system scheduling for unattended work.

| Approach | Status and lesson | Revisit when |
|---|---|---|
| Termius, SSH, and Mosh phone shell | Retired after hands-on use. Roaming shell transport did not make terminal transcripts or approvals usable on a phone, and arbitrary shell access exceeded the actual need. | A recurring non-agent phone-shell workflow appears. |
| Zellij sessions and layouts | Retired after hands-on use. Attach/detach worked, but layouts and multiplayer were not used enough to justify a permanent multiplexer. | An arbitrary local process must survive terminal closure and cannot be owned by launchd or a project service. |
| Zellij resurrection | Retired after implementation. Serialized layouts did not restore process state; exited-session discovery, pruning, and lifecycle rules added more complexity than continuity. | Reliable process restoration exists and a concrete workflow needs it. |
| Zellij web and Tailscale Serve | Retired after hands-on use. A browser terminal required another daemon, token lifecycle, publication path, and small-screen terminal UI while remaining inferior to an agent-aware client. | Paseo fails a reproduced workflow and arbitrary browser-terminal access is explicitly required. |
| tmux | Retired after installation and evaluation as the simpler Zellij replacement. It reduced multiplexer complexity but still had no remaining job once phone-shell access was dropped and Paseo owned agent runs. | A measured local process-continuity need appears. |
| cmux | Retired after comparison with the local terminal/session stack. It did not improve comprehension enough to justify another terminal workspace, and Paseo removed the mobile session-manager requirement. | Multiple simultaneous local agent sessions become hard to understand with Paseo and ordinary terminals. |
| Mission Control Textual TUI | Retired after implementation. Session previews, process-to-session matching, resurrection, attach/create/kill actions, and keyboard navigation made a launcher, not a cross-harness transcript viewer. | Cross-session visibility becomes recurring friction and an existing agent-aware client cannot provide it. |
| Session wrapper CLI | Retired after implementation. Managed names, project association, lifecycle commands, and previews created a second process model around tools that already own sessions. | A non-agent workflow requires a durable session abstraction. |
| Pi-specific remote shortcut and phone PWA | Retired after use. A Pi-only surface could not satisfy the requirement to control Pi, Claude Code, and Codex uniformly. | One harness deliberately becomes the exclusive mobile environment. |
| Open WebUI Computer | Retired after trial. A general browser-hosted computer surface was much broader than agent control. | A recurring remote-computer workflow cannot be served by native screen sharing. |
| Standalone Paseo CLI | Retired after protocol drift caused a stale daemon/client pairing. Use the CLI bundled with Paseo.app so the desktop and daemon versions remain aligned. | Paseo guarantees independent CLI compatibility and the separate package supplies a necessary capability. |
| Generic background-process manager inside Pi | Rejected. The shell, launchd, project task runners, project service definitions, CI, and Paseo already have narrow ownership. Adding supervision to Pi would mix interactive reasoning with process lifecycle. | A recurring process cannot be represented by any existing narrow owner and specifically requires Pi session state. |
| Conductor, AgentHub, agent inboxes, and similar fleet control planes | Rejected for the current workflow. They optimize concurrent agent volume and hide more execution state than the one-parent, bounded-delegation model permits. | Repeated measured work shows that bounded delegation is limited by cross-session coordination rather than task decomposition. |
| Yazelix and sesh | Rejected as extensions of retired foundations. Yazelix compounds Zellij into a terminal IDE; sesh adds a picker around tmux. | Their underlying multiplexer earns a concrete job again. |

Do not retain one of these as a speculative fallback. A fallback needs a reproduced failure and a narrower owner than the retired system.
