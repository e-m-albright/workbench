## Proposed, not active

- **Vite+ workflow consolidation and Solid comparison:** Vite+ is watch-only after the completed [runtime comparison](../playbook/languages/typescript/runtimes.md). Revisit only when it demonstrates configuration removal or useful repeated feedback improvements while preserving framework coverage. The separate [Solid/SolidStart trial](../playbook/languages/typescript/frameworks/solid.md) keeps the runtime fixed. Neither trial is active. Review a framework trial after one complete representative feature and its integration checks; adopt one implementation or remove the trial configurations and dependencies.
- **Hosted coding sandbox or credential gateway:** compare a disposable remote job with the local/CI baseline, or Claw Patrol with one read-only service, using the [security exploration](../playbook/agents/security.md#hosted-sandboxes-and-credential-gateways). This is a concrete candidate set for the provenance-aware execution proposal below, not a second control plane. Review after one synthetic canary; remove the environment, credentials, and adapter if useful completion and isolation do not justify the added operations. No paid run or private repository upload is active.

- **Cursor-style repository automation:** schedules, repository events, tightly scoped tools, explicit no-op outcomes, and a small deduplication ledger are credible patterns for recurring repository maintenance. Do not build a scheduler into Pi. Start a trial only when one concrete workflow recurs often enough to name its trigger, permissions, output destination, cost ceiling, and deterministic verification. Prefer GitHub Actions or the private automation layer as the runtime.
- **Provenance-aware sandboxed execution:** soft rules plus provenance tracking, a disposable credential-free workspace, default-deny egress, and parent-owned patch adoption are the credible response to indirect prompt injection. A future trial must isolate the filesystem and process space, account for DNS, redirects, proxies, loopback, metadata services, and alternate address forms, and keep reusable credentials outside the sandbox. Any authorized request should pass through a trusted broker that injects task-scoped authority, records the destination and operation, and can reduce permissions after setup. No trial is active. Revisit only when a recurring task requires execution against untrusted web, archive, package, or unfamiliar-repository content and the current explicit sandboxed-harness fallback proves materially restrictive or unreliable. Start with one bounded execution profile; do not build a universal classifier, taint engine, or general network broker before the workload exists.
- **Direct assistant versus owned business API:** compare a supervised read-only connector or skill with one application-owned reconciliation slice when a real workflow needs two sources and a proposed write. Measure setup time, source attribution, authorization gaps, review effort, recovery from ambiguous writes, and reuse across assistant clients. The owned slice should expose only normalized read, discrepancy, proposal, approval, and commit operations; keep canonical rules, process versions, audit, and idempotency in the service. Run this in the owning application with synthetic or narrowly scoped data. Review after one complete workflow and remove the experimental connector and endpoints if they do not reduce errors or repeated work. The [boundary rationale](../playbook/agents/integrations.md#direct-agent-integrations-and-application-owned-boundaries) is documented separately; no trial is active.

## Completed

- **Workbench Bun adoption trial (closed 2026-10-14):** restored Node LTS, pnpm, and the existing TypeScript, Vitest, Biome, and Oxlint tools. Bun's installer, checker, and credential-free Pi probes worked, but did not demonstrate enough tooling removal to justify another runtime. Preserve the independent permission-guard correction found during testing. Bun and Deno remain explicit [ecosystem watches](../playbook/watchlist.md#engineering); neither is an active migration.
- **Disposable JavaScript runtime comparison (2026-10-12):** Node and Node with Vite+ passed selected checks and tests on two maintained web applications. Bun had modest build gains and a larger relative gain on a subsecond script, but failed current jsdom setup. Keep Node/pnpm as the runtime default and Vite+ on watch for demonstrated workflow consolidation. The [runtime exploration](../playbook/languages/typescript/runtimes.md#local-comparison-and-next-adoption-gate) preserves generic measurements, limitations, and the reduced compatibility finding. Original applications and host installations were unchanged; disposable copies and raw logs remain outside the repository for review.
- **Disposable Oxc versus Biome evaluation (2026-10-12):** Oxlint demonstrated useful type-aware findings missed by Biome 2.5.15, but full replacement did not preserve Astro formatting and non-JavaScript lint coverage. Oxfmt's Svelte output passed framework checking and 198 tests; one component needed a second formatting pass to stabilize. Keep Biome as the baseline; the owner approved adopting the two focused Oxlint promise checks after this evaluation. The [evaluation](../playbook/languages/typescript/runtimes.md#disposable-oxc-versus-biome-evaluation) records accuracy controls, policy gaps, and limits. Original applications were unchanged.
- **Pi native fullscreen versus Transcript Reader (closed 2026-08-26):** adopted native fullscreen and retired the custom reader. The result and revisit trigger live in [`decisions/tombstones.md`](decisions/tombstones.md#retired-pi-harness-experiments).
- **Cross-harness mobile viewer (closed 2026-08-26):** standardized on Paseo over Tailscale. The retired Pi-specific and terminal variants live in [`decisions/tombstones.md`](decisions/tombstones.md#terminal-continuity-mobile-access-and-process-runners).
